# 外部邮箱的个人设置与后台设置

后台入口：系统设置 → 外部 IMAP（外部邮箱服务）。管理员设置总开关、全部用户或指定用户、凭据加密密钥、同步间隔以及共享 Google / Microsoft OAuth 应用。共享 OAuth 应用只提供授权登录入口，不共享任何用户的邮箱账号。管理员自己的账号也受指定用户范围约束。

个人入口：设置 → 外部邮箱（`/profile?tab=external`）。每位用户分别添加外部 IMAP 收信账号，并可在“我的 Gmail 发信通道”中配置自己的 Gmail。账号、加密密码和发信规则均按用户 ID 保存；服务端校验权限与归属。

生效顺序：后台授权 → 当前用户的个人配置 → 收件厂商匹配。未启用个人发信规则或未匹配厂商时使用原有发信通道。匹配 Microsoft / Yahoo 的收件人使用该用户的 Gmail；Gmail 失败会报错并按队列规则重试，不静默改用原服务器。撤销权限会阻止新的外部连接和同步操作，保留已保存的账号配置。

## 个人 Gmail 的限制

需要 Google 两步验证和 16 位应用专用密码，不使用 Google 登录密码。IMAP 收信与 SMTP 发信分别配置；仅添加收信账号不会自动启用发信路由。SMTP 固定使用 `smtp.gmail.com:465` 加密连接。

Gmail 发送时 From 使用配置的个人 Gmail，原回复目标保存在 Reply-To，正文与附件保留。个人 Gmail 不是可任意使用自建域名发件人的商业中继，Google 发信限额及风控仍然适用。厂商匹配为明确支持的公共邮箱域名，不通过 MX 推断企业自定义域名。

混合收件人拆分投递；已接受收件人保存提交标记，普通重试跳过这些收件人。SMTP 接受后、标记落盘前发生故障仍有重复投递窗口，需要管理员检查，不能保证跨 SMTP 和本地存储的绝对原子性。

保存设置不会发送测试邮件，也不表示凭据已验证。生产启用需要用户自行填写凭据，并完成真实投递验收。

## 更新与回退

数据库新增 `personal_smtp_routes` 表，不删除现有数据。更新前备份数据库、环境配置和凭据加密密钥。回退到旧版本时保留新增表，旧程序不会使用个人路由；后台用户范围由新版本执行，旧版本不提供此限制，因此依赖限制隔离时不要直接回退到全局开启的旧版本。

本次验证覆盖个人配置隔离、后台范围持久化、旧客户端不重置权限、撤权后的 OAuth 回调与同步、凭据加密、混合收件人重试和 MIME 保留；前端通过类型检查与生产构建，并使用本地合成账号检查桌面和 390px 手机视口。尚未据此完成真实 Gmail 投递或生产部署。

## 后台账号池与个人覆盖

管理员在后台外部 IMAP 页面开启服务后，可以全选、清空或单选/多选用户。被选中的用户在个人设置中看到“外部 IMAP”。后台账号池可以绑定多个 SMTP 账号，支持固定单账号或按每轮收件人数轮换；账号池密码只在服务器加密保存。

后台可以选择“全部收件厂商（相当于全选）”，也可以选择微软、Yahoo、Google、QQ、网易、苹果、Proton 等公共厂商，并补充企业自定义域名。命中厂商的手动发信和自动转发使用账号池；未命中收件人使用原服务器。同一封邮件的不同收件人会拆分投递。个人用户默认继承后台配置，也可切换到个人账号池；个人池只影响本人。

IMAP 负责从外部邮箱收信，SMTP 负责向外部收件人发信或转发。两者在页面上同属“外部 IMAP”功能，但凭据和运行路径分开保存。外部 SMTP 主机只允许公开 IP，连接前会解析并拒绝内网、回环和 link-local 地址；仅支持 TLS 465 或 STARTTLS 587。个人或后台输入的 SMTP 主机不会直接用于任意内网连接。
