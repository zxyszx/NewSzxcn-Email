# 按收件邮箱厂商选择 SMTP 中继

后台「系统设置 → SMTP」中的“通过中继发送的收件邮箱厂商”控制正常发信、客户端提交及转发队列的出站通道。

- 全部厂商：所有队列外发邮件沿用现有 SMTP 通道，兼容升级前行为。
- 常用国内外邮箱厂商（国内 QQ、网易；国外谷歌、微软、雅虎）：可多选；命中的收件人通过下方 SMTP 通道发送，其他收件人经本机 Postfix 直接投递。
- 自建域名 / 其他域名：填写完整域名，使用逗号分隔，精确匹配，不自动包含子域名。
- 全部取消：所有队列外发邮件经本机 Postfix 直接投递。

例如仅选择微软、雅虎，并配置可用的中继主机、端口及认证信息，Outlook / Hotmail / Yahoo 等收件人使用中继，其他收件人继续直发。SMTP 测试按钮只测试所配置的 SMTP 通道，不按收件人分流；先保存设置，再测试。

## 厂商识别

界面默认仅列出五类常见邮箱，按国内（QQ、网易）和国外（谷歌、微软、雅虎）分组，另有“全部厂商”和“自定义域名（含自建邮箱）”。其他需要中继的邮箱可先添加完整收件域名临时使用，之后按需要扩展厂商选项。后台保留扩展识别目录；已有的其他厂商选择会显示在“其他已选厂商”，避免规则被隐藏。完整目录及公开域名、MX 规则保存在 `apps/api/internal/app/smtp_providers.json`，前后端共用，避免界面选项与后台支持范围不一致。全球邮箱服务无法穷举，未列出的厂商使用完整收件域名配置。

常见公开邮箱域名直接识别；自定义企业域名查询 MX 记录，识别目录中支持的企业邮箱接收端点，包括腾讯企业邮箱、网易企业邮箱、阿里邮箱、飞书、Lark、Microsoft 365、Google Workspace、Yahoo、Proton、Fastmail 和 Zoho 等。部分厂商仅支持公开邮箱域名识别；未收录或无法识别的企业域名可通过“自建域名 / 其他域名”指定。MX 主机按完整后缀边界匹配。无法识别或混合厂商的 MX 走直发，自定义域名规则可用于覆盖网关代理等识别不到的情况。

按厂商分流时，本站启用的邮箱域名直接交给本机 Postfix，不查询公网 MX；“全部厂商”保留旧版全局 SMTP 行为。

DNS 查询失败时不绕过路由规则直发，而是保留队列失败并按原有队列策略重试。单域名查询最多 5 秒，一封邮件的厂商识别最多 30 秒。这里不尝试先直发、拒收后再换中继，避免投递结果不确定时重复发送。

## 两条通道

SMTP 通道使用后台现有的主机、端口、认证及强制 TLS 设置。外部服务商通常使用 587 STARTTLS 或 465 TLS。

本机 Postfix 通道独立配置主机及端口，不携带中继用户名和密码。整合部署通常为 `127.0.0.1:25`；分组件部署应填写容器内可达的 Postfix 服务名，例如 `postfix:25`。分组件 Compose 已默认使用 `postfix:25`，自定义主机使用 `LANQIN_STACK_SMTP_DIRECT_HOST`。不要填写外部收件方的 MX 地址。

中继必须支持你的发件身份及域名认证。本功能不改变 From 或 Reply-To，不能使普通 Gmail 自动具备任意自建域名的代发权限，也不保证对方接受邮件。需要按所用服务配置 SPF、DKIM 和 DMARC。

## 混合收件与重试

同一封邮件的收件人按通道分组，原始邮件头保持不变，密送地址不会添加到邮件头。每组 SMTP DATA 收到成功确认后，将成功收件人记入新增的 `send_queue_recipient_receipts` 表。另一组失败或进程正常重启后，重试跳过已记录成功的收件人。主动重新提交终态任务则清除该任务旧记录，作为一次新发送。

SMTP 在接收确认与本地记录之间仍存在进程崩溃窗口，无法保证严格的恰好一次投递。DATA 已确认后，QUIT 断连不会被当作投递失败；DATA 确认本身丢失时，仍有 SMTP 固有的不确定性。

## 环境变量与兼容

后台保存的设置优先于环境变量：

- `LANQIN_SMTP_RELAY_PROVIDERS=all`：`all`，或逗号分隔的厂商标识，例如 `tencent,netease,microsoft,yahoo,google,custom`；`none` 表示全部直发。
- `LANQIN_SMTP_RELAY_DOMAINS=`：逗号分隔的完整收件域名。
- `LANQIN_SMTP_DIRECT_HOST=127.0.0.1`。
- `LANQIN_SMTP_DIRECT_PORT=25`。

升级默认保留全局 SMTP 行为；旧客户端不提交新字段时保留当前规则。新增表不修改历史邮件或原队列字段，不删除任何数据。回到旧版时，旧版不会读取收件人成功记录；应先处理完部分发送的任务，避免旧版重新发送整封邮件。更新前保留当前数据库、邮件和配置备份。
